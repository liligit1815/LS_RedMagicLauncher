# 视频参考：右侧扇形最近任务

本轮参考为用户提供的《桌面最近任务样式.mp4》。素材是视频编辑器的屏幕录制：原图 1280 × 2772，共 355 帧，解码平均帧率约 24.3665 fps、时长约 14.57 秒。真实演示只占画面中间约 y = 755～1480 的横向视频区域。演示中还包含镜头放大、平移和第二次播放，不能把整个录屏的尺寸或镜头位移当成最近任务布局。

两轮演示基本重复。只凭视频看不到手指坐标或触摸轨迹，所以“向下滑动对应卡片向下滚动”是根据卡片运动推断的交互方向，不是触摸事件实测。视频没有展示左右滑动删除、长按菜单、锁定、横屏或空列表；这些功能必须按红魔原有行为和独立验证处理，不能声称已从参考中还原。

## 布局量测

以第 132 帧为完整设备基准，视频局部坐标内屏幕约为 `(284, 44)～(889, 699)`，宽约 605、高约 655 像素。卡片边缘受圆角、压叠和视频压缩影响，人工定位误差约 3～6 像素。下列中心不包含左侧名称气泡或上下压叠的其他卡片：

| 从上到下 | 局部像素中心（约） | 相对屏幕中心（约） | 顺时针角度（约） |
| --- | --- | --- | --- |
| MT 管理器 | (809, 185) | (0.868 W, 0.215 H) | 10～12° |
| 相册 | (795, 272) | (0.845 W, 0.348 H) | 7～9° |
| QQ | (785, 362) | (0.828 W, 0.485 H) | 4～6° |
| 微信 | (780, 450) | (0.820 W, 0.620 H) | 1～3° |
| 设置 | (780, 545) | (0.820 W, 0.765 H) | 约 0°，偶有轻微反向 |

单张主要内容宽约 68～74 像素（约屏宽 11～12%）、高约 82～92 像素（约屏高 13～14%），中心竖向间距约 90 像素（约屏高 14%）。视频演示的是接近方形的折叠屏内屏；红魔长屏必须按可用宽高与卡片原始比例重新适配，不能直接抄录屏像素尺寸。

视觉重点是**右侧竖向浅弧、等大的小卡片、名称在左侧**。上卡比下卡更靠右、顺时针转角更大；下卡接近竖直。卡片没有绕屏幕中心排列，也没有前大后小的三维透视。五张主要卡之间留有小缝，端部还可以看到其他卡短距离压叠；视频未提供足够信息重建端部全部隐藏历史的数学轨迹。

标题是白色圆角气泡、黑字、位于卡片左侧并与卡片一起略微旋转。桌面保持可辨认，没有强烈暗幕遮住背景。右下 Dock 的入口在展开后变为向下收起符号。参考没有展示全部普通最近任务操作，因此 Dock 入口及其图标也不能直接推断为红魔现有手势入口。

## 本轮几何约定

`LsFanGeometry` 使用五个主要槽位：`y/H = .20, .34, .48, .62, .76`。对应 `x/W ≈ .869, .843, .825, .814, .810`，转角 `10°, 7.5°, 5°, 2.5°, 0°`。这是对参考浅弧的近似拟合，不是宣称视频原实现的精确参数。

归一化横坐标使用 `x = .81 + R − √(R² − (.76 − y)²)`、`R = 2.70`。该参数空间的弧心为 `(3.51, .76)`，在屏幕右侧很远处；宽高各自归一化后适配，因此长屏上的物理轨迹是浅椭圆弧，并非固定像素半径的圆。所有卡片缩放比相同；卡片实际尺寸由布局层决定。

历史浏览是有界窗口：`page ∈ [0, max(count − 5, 0)]`，首尾不循环。窗口上下各一槽淡出，完整不透明卡片不超过五张，滚动中最多六张有非零透明度。少于五张时维持间距并把整组中心放在 `y/H = .48`；少任务布局和有界浏览属于本轮适配设计，参考未展示少任务情形。

## 红魔接入与操作

最近任务样式新增第五项“扇形卡片”，保存值 `5`；原有 `1/2/3/4` 保留。设置项与预览由 Java 注入，不修改原厂资源 ID、APK 资源、原生库或父模块。该样式首版内部版本为 `260024`，显示版本仍为 `26.9.260.908.2609081608`。

- 上下滑动浏览有界历史，松手带惯性并吸附；短按打开，长按回正放大后显示已有侧边操作。卡片向左滑动超过视口宽度的 10% 后调用原厂移除，锁定卡不移除；这些操作是红魔适配，不是视频中全部展示过的动作。
- 100% 比例时，卡片宽度不超过视觉视口的 15%、高度不超过 13%，取共同缩放以保留截图比例。由上到下的内容区域不压住原厂清理按钮；本机竖屏和横屏五卡已验证。扇形小卡圆角限制为截图短边的 10%，避免原厂固定屏幕半径把小卡变成胶囊，打开时按全屏进度恢复原厂终点。
- 从 260025 起，扇形有独立的 70%–120% 比例滑条，默认 100%；仅调整扇形卡片大小，保持浅弧位置。堆叠与环绕比例不影响扇形。设置预览复用堆叠的冰蓝视觉。
- 名称使用白色圆角标签在卡片左侧绘制，保持屏幕可读字号；跟随所属卡片的位移、倾斜与透明度。原卡片顶部名称和图标在此样式中隐藏。异步标题写入及缩放、方向、菜单显隐变化会更新父视图的绘制缓存，长按展开与收回期间隐藏名称，回到弧线后恢复；卡片透明度由整层统一处理。
- 桌面入口从视觉右侧露出；应用入口沿当前手势动画交接。没有新增视频中的折叠屏 Dock 入口，继续使用红魔最近任务入口和背景流程。长按的选中卡放大回正，关闭菜单后返回原弧线。
- 打开时保存截图的旋转四边形，沿同一原厂进度回正、放大；其余卡按现有退出规则退开。位图、旋转元数据和内部绘制矩阵从截图视图自身读取，避免任务缓存已更新、视图仍显示旧截图时误用另一份数据。
- 截图与实时窗口方向不同时，旧截图和新应用可能已采用不同内容布局。此时保留沿同一矩阵移动的截图，并暂时隐藏实时窗口；等原厂实时窗口淡入阶段完成，再将实时窗口设为不透明并一次性隐藏截图，避免混合两套内容。原厂不执行淡入的路径在打开动画终点交接。该阶段条件不代表应用缓冲区已经就绪的证明，也不承诺像素无缝；本机横屏切换仍可见内容布局和圆角变化。
- 原厂要求隐藏窗口或目标无效时保留截图；取消、失败、新入口与样式切换恢复截图透明度并清理临时旋转、分页和动画状态。

主要实现是 `LsFanGeometry`、`LsFanPager`、`LsFanReflow`、`LsFanChrome`、`LsFanStyleSettings`，共同入口与布局在 `LsNativeStack`，打开交接在 `LsStackTransition`。窗口不创建重复任务视图，删除补位绑定任务身份并使用原厂移除动画的进度。

## 验证范围

`tools/test-launcher-fan-geometry.py` 编译并运行实际 Java 几何类，覆盖参考布局、浅弧方向、等大卡片、短列表居中、首尾夹紧、连续浏览、窗口淡出、横竖尺寸变化和异常输入。该测试不证明 Android 绘制结果、手势命中或设备动画帧率。设备安装和人工验收状态以 `docs/DEVELOPMENT_STATUS.md` 及当轮实际验证结果为准。

2026-10-04 按用户当时要求仅构建；2026-10-08 用户后续授权安装测试，已在 NX809J 完成本轮定向检查，并修复实测的标签缓存、小卡圆角及横屏打开交接问题。最终横屏录屏的连续帧未见双影或白场；竖屏打开的 114 个连续帧检查通过，锁定与删除操作也已定向验证。横屏交接中的内容布局和圆角变化仍可见，不能描述为像素无缝。最终安装包身份、构建结果、设备回拉校验与交付路径统一见 [当前开发状态](DEVELOPMENT_STATUS.md)。
