# 260007：上滑右侧任务卡却带动中间卡

显示版本保持 `26.9.260.908.2609081608`，内部版本为 `260007`；固定验收基线仍为 `260005`，保留 `260006` 的横屏入场修复。

## 现象与根因

2026-09-25 用户提供的第二段录屏显示：堆叠最近任务中，右侧卡片覆盖中间卡片的一部分，上滑右侧重叠区域时，中间卡片反复上移、回弹；更靠右的触点则能带动右侧卡片。

`LsNativeStack.findTouchedTask()` 原先先检查逻辑焦点卡的整个变换后矩形，主动忽略其可见裁剪范围，并在命中时立即返回。右侧卡片虽然视觉层级更高，仍没有机会参与这个区域的手势选择。命中结果由原厂 `K` 控制器保存为本次拖动任务，因此动画实际跟随的是中间卡片。

## 修改

- 移除焦点卡优先返回的例外；所有任务都通过相同的透明度、原厂可见性、变换后边界和可见裁剪检查。
- 在覆盖触点的候选中选择 `translationZ` 最大的卡片，与当前堆叠显示顺序一致；裁剪为阴影保留的小段重叠也归更高层卡片。
- 将选中卡片交给既有手势缓存和原厂控制器；原厂样式仍绕过堆叠命中处理，未更改删除、取消、下拉锁定或补位动画实现。
- 同步辅助 Java 与打包 Smali，并从 `src/apktool.yml` 更新内部版本。

## 自动化验证

`tools/test-launcher-touch-target.py` 提取并编译真实生产命中方法，用明确的几何输入验证选中任务和缓存任务。旧实现对右侧重叠触点返回中间卡片，检查失败；新实现通过 53 项检查，覆盖三种子视图顺序、左/中/右卡、阴影重叠、空白区域、透明/不可见卡、取消时未裁剪的重叠卡、缩放与偏移、裁剪边界、单任务、无任务和非堆叠样式。另检查原厂控制器接收所选任务，并保留无命中结果。

该检查已加入统一构建，与原有入场、删卡补位、样式隔离、焦点绘制检查一起执行。几何测试使用模拟 Android 边界，不能替代真机输入分发和动画时序验证。
