# 260010：最近任务入场抖动与动画连续性

显示版本保持 `26.9.260.908.2609081608`，内部版本 `260010`。固定验收基线仍为 `260005`，保留前几轮的横屏、卡片命中及小窗修正。

## 反馈与证据

用户反馈进入最近任务时卡片先左右抖动、随后恢复堆叠，且入场、手势条切换后台及左右侧滑生硬。提供的约 10.63 秒录屏中，约 1.26–1.50 秒能看到卡片从左侧露出，再横向移动并形成堆叠。录屏约 24.74 fps，不能用于证明手机实际刷新率或统计高刷新屏幕的丢帧率。录屏及抽帧只保存在本地忽略目录，不包含于公开源码。

源码中可重现的干扰包括：重复的 Overview 状态通知重新捕获任务顺序并定页；加载回调替换已经显示的入场顺序；入场和触摸时跳过坐标校正，原厂直接写入 View 位移后，下一次计算仍减去旧堆叠位移，导致错误的补偿；桌面入口尚未确定任务身份时，第一张缓存卡片仍可显示。此外，明确选择 RECENTS 的瞬间，实时画面的滚动被直接清零、中心被直接移至目标位置，缺少交接过渡。

这些是主机测试可确认的路径，不能将它们等同于录屏全部现象的唯一原因，或声称 Android 渲染流畅度已经验收。

## 修改

- 同一视图重复进入 Overview 的通知不重新开启入场事务；应用手势启动时清除上一轮活跃入口，保证真正的下一次进入仍能选卡。
- 加载回调刷新原有任务身份绑定，保持有效的入场顺序，避免重新抓取首卡。
- 最近任务激活期间，每次合成前恢复由 TaskView 原厂字段和堆叠字段组成的位移、缩放和透明度，再计算本帧堆叠位置；原厂删除位移仍叠加生效。离开最近任务后不扩大这项校正的范围。
- 桌面和应用入口都等待有效任务身份，避免先显示尚未确认的缓存首卡。
- RECENTS 实时画面的中心、深度缩放和滚动修正随原厂动画进度逐步生效，起点保留原厂输入，终点保持既有堆叠几何及旋转映射。保留原厂保存的滚动输入，仅在绘制时采样一次，避免重复衰减及缓存旧进度。
- 原厂应用手势持有视图期间，实时画面目标缩放不额外乘堆叠缩放；明确提交 RECENTS 后恢复。
- 每次原厂入场动画进度更新请求重绘，覆盖长按上滑已经到终点、但第二张卡片仍需移动的情况。没有新增动画器或固定延时。

## 同轮追加：左右滑动闪屏、切后台左右抖动

用户继续反馈左右滑动时闪一下、切后台左右抖动。此次没有新的录屏或连接设备，以下为源码确认的额外不连续路径，不能据此声称已复现或消除全部实机现象。

- 原厂 `loadVisibleTaskData` 按普通分页范围判断加载/卸载。堆叠后方仍露出的卡片可能落在范围外，进入 `onTaskListVisibilityChanged(false, …)` 清理截图。现在在原厂卸载判断前，额外保留堆叠可见卡片及前后一个分页行程需要的截图；仍保留原厂已要求加载的任务。原厂手势持有视图和其他样式使用原判断，关闭最近任务时仍使用原厂卸载流程。
- 选定 `RECENTS` 时，入场、加载及排队回调会立即把实际分页对齐到第二张卡，改变实时动画的滚动输入。现在实时入场期间只推进堆叠的逻辑视口，实际分页在完成交接或用户接管时对齐；桌面入口仍即时对齐。
- `test-launcher-thumbnail-continuity.py` 执行实际几何与保留判断：13,689 项断言覆盖正反滚动、1/2/6/40 个任务、可见范围和双向预加载、绑定顺序、删除视口、样式与原厂手势隔离、保留数量上界，以及实时动画期间禁止提前跳页。修正前源码在提前跳页断言失败；仅加入分页修正、保留原厂相邻两页加载范围的对照，在第四张卡的可见/预加载断言失败。
- 生命周期测试改为执行真实 `setEntryPageAligned`，不再用直接跳页的替身；561 项断言通过，增加连续入场通知、加载回调和绘制后仍保持实时分页输入、完成后再聚焦第二卡的检查。
