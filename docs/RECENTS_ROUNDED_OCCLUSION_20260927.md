## 消散阶段竖线反馈后的追加修正

用户提供 `Screenrecorder-20260927-132013.mp4`（1216×2688，约 13.55 秒）。约 4.51 秒的设置卡片与后方卡片在半透明阶段出现清晰亮线。此反馈说明之前的不透明边界回归不足以覆盖退出消散，不代表上一追加包已验收。

生产路径中的一像素轮廓保护补齐了不透明卡片的交界，但原厂内容透明度逐张作用于 TaskView。两个重叠像素在透明度为 a 时合成覆盖率为 `2a-a²`，半透明时比卡片内部更亮；仅继续缩小保护范围会重新暴露漏缝。当前修正仅在有效堆叠返回桌面事务中，将任务卡片先合成到同一个临时图层，再用原厂内容透明度淡出一次。层范围沿用当前 Canvas 的变换和裁剪；清理按钮等非任务卡片在图层之外绘制。

原厂子视图遍历分两次过滤，卡片和其他控件各实际绘制一次，保留原厂层级、可见性和页绘制行为。TaskView 保存的 stableAlpha 仍是原值，绘制值去除公共 contentAlpha 后才乘卡片原有深度透明度。内容透明度改变时主动重绘父层，避免子 RenderNode 透明度恒定造成消散停住。取消、完成、重入、样式切换及启动应用前恢复原绘制透明度。Canvas 和遍历过滤状态在异常路径也恢复。不增加独立时钟，不改变圆角遮挡或点击应用的远端 Surface 路径。

回归执行生产 Java 与实际 Smali 的子视图过滤分支，覆盖 101 档内容透明度、33 个抗锯齿覆盖相位、独立卡片透明度、深度透明度、控件隔离、取消与完成清理、父层重绘和绘制异常。共 102,845 项退出/启动及新增合成检查通过。这些主机检查覆盖像素模型，不包含 Android GPU 输出与临时离屏层的实际帧耗时。

临时恢复逐卡透明度以及移除父层重绘通知，两项负向验证均按预期失败；旧路径比较排除整数层透明度量化的差异，直接捕获交界重复叠加。

## 1.mp4 实测反馈后的追加修正

用户测试初版后提供 `1.mp4`（576×1280，314 帧，约 10.86 秒），确认 QQ 卡片左侧仍有明显竖线。同一 QQ 截图随滑动位置变化，竖线会出现和减弱；约 9.83 秒处最明显。此反馈说明初版的 CLAMP 和半像素轮廓保护不足，不能将初版主机回归通过写成竖线已实机修复。

本次补齐两条可复现的绘制缺口：

1. 系统“不透明任务”元数据与位图实际边缘 texel 的 alpha 是不同信息。CLAMP 只重复边缘采样，无法填补边缘 texel 自身的透明度。完全覆盖的不透明任务截图现在通过 ComposeShader 将原卡片底色置于截图之下，再用原截图画笔只绘制一次圆角。原 dim 色彩过滤器对合成结果应用一次，不新增独立圆角底图、不扩大截图范围，不新增离屏图层。真实透明任务、缺图、锁定、私密、启动占位、留边和非堆叠守卫不变。
2. 前卡圆角与后卡反向裁剪是独立栅格化的。半个屏幕像素的保护在部分小数位置仍会使两个边界同时只有部分覆盖。轮廓保护改为一个实际屏幕像素，补足这一边界的采样范围；尺寸不随密度变成 dp 宽条。新增用例读取生产几何，在 63 个像素相位、多个缩放及方向下检查等色卡片交界不能透出深色壁纸。

底色、截图或矩阵改变时更新对应缓存；绘后恢复 OEM Shader，图像刷新时释放旧缓存。合成子 Shader 的矩阵失效追踪及 SRC_OVER 输入顺序核对了 [AOSP ComposeShader](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/graphics/java/android/graphics/ComposeShader.java)。API 33 以上显式设置线性采样，保留原截图画笔的过滤效果；API 31/32 不调用新接口。两种采样路径的主机 API 守卫已覆盖。

追加检查：14,405 项生产轮廓/缓存/交界回归；2,592 项真实 Java Shader 工厂的边缘透明度、底色、Alpha 与单次圆角合成检查；真实 Smali 缓存、换色、换图、矩阵及恢复路径通过。保留 32,768 条透明性分支、120 项覆盖几何、7,806 项 float32 缩放和 1,728 项既有合成检查。临时恢复半像素保护会失败于交界透出壁纸，恢复裸 CLAMP 会失败于边缘透明度；均在临时副本执行，未回退业务源码。

这些检查验证了新增防护的行为，不能从录屏单独断定全部竖线都由某一种机制产生，也不能代替目标 GPU 实测。该次 QQ 追加修正记录的是主机轮廓、缓存、交界与合成检查。

## 初版证据与修正

用户提供 `Screenrecorder-20260927-121520.mp4`，约 9.19 秒。左右滑动时，前卡左上、左下圆角与后卡交接处可见直角缺口；卡片侧边可见细线。录屏包含应用内容，只在忽略的本地输出目录保存分析帧，不提交原片或截图。

原 `TaskView.drawChild` 使用贯穿全高的矩形裁剪。即使 X 边界使用浮点数，前卡圆角外本应露出的后卡仍被删掉；该处露出壁纸，看起来像直角阴影。`LsStackOcclusion` 现在将所有更高层、可见截图的实际矩阵、尺寸和当前圆角半径映射到后卡坐标，再按完整二维轮廓排除遮挡。截图上方标题边距不再当成截图遮挡。多容器和多个前层截图分别参与计算。

仅截图子视图使用轮廓；名称、图标、操作按钮保留既有裁剪和显示规则。手势的保守矩形命中范围及远端窗口的矩形 crop 接口保持。长按展开采用现有可见宽度扩张量平移轮廓，收回时反向恢复。裁剪关闭、非堆叠和前卡不可见会清除轮廓。

轮廓按全部卡片的位置更新完毕后生成。只有几何变化才重建 Path 并使 TaskView 重绘；半径、Y、大小变化不会因为旧 X 裁剪未变而漏掉更新。状态使用弱键和独立几何数组，不持有其他任务视图；退出保存、属性恢复和取消回退复制轮廓，不引用后续帧的可变数组。

侧边细线还有透明采样风险：高通路径使用 DECAL，缩放过滤可在截图边缘混入位图外的透明色。已通过 `260019` 不透明性及完整覆盖判断的截图，绘制时临时使用 CLAMP；它只复制边缘像素，不扩大截图范围。矩阵每次同步，任务换图时重建，绘完恢复原画笔。真实透明、隐私/锁定/启动占位、缺图、非堆叠、留边及自定义画笔保留原处理。轮廓内缩半个实际屏幕像素，让前卡抗锯齿边缘保有底下的后卡；这不是恢复此前 3dp 整张截图重叠。
