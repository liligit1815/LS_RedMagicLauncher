# 260006：横屏应用进入最近任务时实时画面错位

显示版本保持 `26.9.260.908.2609081608`，本轮内部版本为 `260006`。固定回归基线仍为用户已验收的 `260005`。

## 复现与根因

2026-09-24，在 NX809J、Android 16 / API 36、RedMagicOS 11.5.7MR1 上，用 USB ADB 从王者荣耀底部上滑并停顿进入堆叠最近任务。260005 的三次有效录屏均出现实时游戏画面与背景卡堆错位，实时动画结束后归位。长停顿样本在松手前居中，松手后下移，约 0.4 秒后完成实时画面与任务截图的交接。再次进入时，错位也可能提前到拖动阶段。

原 `normalizeLiveEntryMatrix()` 直接使用 Launcher Resources 的宽高计算目标 X/Y，而传入矩阵已经应用了窗口旋转。设备横屏窗口为 2688×1216，Launcher Activity 仍可按 1216×2688 布局，由方向处理器呈现横屏卡片。原修正将横屏中心 Y 定位在 1344，而实际应为 608，相差 736 px；录屏几何估算与这一偏移吻合。实时 surface 退出后，使用另一套方向轴布局的截图卡片接管，所以稍后恢复。

竖屏 Activity/缓冲区搭配横屏方向处理器属于原厂支持的路径。不能仅凭竖向截图中卡片横置判断方向故障；比较录屏时应统一到同一握持观察方向。

## 实现

- `TaskViewSimulator` 每帧把本次实际窗口旋转和窗口偏移保存到可复用矩阵，随 live surface 的矩阵、裁剪区域传给辅助方法。调用方关闭窗口旋转时明确使用单位矩阵，避免继承上一帧旋转。
- `LsNativeStack.normalizeLiveEntryMatrix()` 把实时中心逆映射到桌面布局坐标，用 RecentsView 的实际尺寸和方向处理器计算主轴/副轴目标，再通过同一帧矩阵映射回窗口坐标。单任务保留原厂主轴位置，多任务继续使用既有堆叠中心和缩放曲线。
- 仅在堆叠入场状态生效；未测量布局、无效裁剪和不可逆矩阵直接保留原始结果。复用 Matrix 与点数组，不增加每帧对象分配。
- Java 主类与六个内部类的打包 Smali 已重新生成。内部类变化主要为编译生成的源码行号迁移。

## 可重复验证

`tools/test-launcher-entry-rotation.py` 提取生产 Java 方法，用 JVM 的独立仿射变换实现验证 434 项断言，覆盖 0/90/180/270 度、窗口偏移、禁用窗口旋转、单任务/多任务、入场进度、生命周期和样式隔离，并检查实际 Smali 接入点。该检查已接入 `tools/build-launcher.py`；它不替代 Android 渲染与输入时序的实机验证。

统一构建还执行原有入场选择、旧回调失效、交互取消、删卡几何与接入、样式隔离和焦点绘制检查；强制回编译，核对辅助 Smali 同步、版本、代码边界、原厂资源保真及 16 KB ZIP 对齐。未签名、同签名完整构建均通过（`unsigned_verified` / `signed_verified`）。资源 8,858 项、原生库 8 项、assets 22 项相对 260005 无变化。
