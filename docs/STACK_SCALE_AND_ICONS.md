# 260011：堆叠图标显示与卡片缩放

> 当前 260015 的操作按钮全部默认隐藏，仅长按所选卡片显示其原厂右上角按钮，操作完成或取消后全部隐藏；“更多”菜单实际关闭后才恢复图标和名称规则。下文 260011 的操作区空间判断，以及 260012–260014 的“默认第一张显示”均为历史记录。当前行为见 [入场与长按过渡](RECENTS_ENTRY_AND_ACTION_TRANSITIONS.md) 和 [开发状态](DEVELOPMENT_STATUS.md)。

显示版本保持 `26.9.260.908.2609081608`，内部版本 `260011`。固定验收基线仍为 `260005`；保留前几轮的手势、滑动、删除与横屏修正。

## 用户要求与实现

1. 后方任务卡片的应用图标独立于标题显示。按每个任务容器的图标 Drawable 实际边界、缩放、屏幕边界及上层卡片遮挡范围计算可见比例：完整容纳时清晰显示，部分遮挡时渐变虚化并降低透明度，完全遮挡时隐藏。透明度采用端点斜率为零的平滑曲线，去掉原先最低 45% 透明度的跳变；虚化减至最多 3 dp，细分为 32 档并缓存 RenderEffect，同一档不重复设置。空间恢复及退出堆叠时清除效果。图标自身透明度导致的 `INVISIBLE` 不作为永久隐藏条件；`GONE`、未绑定 Drawable 和未完成布局的图标仍不显示。原厂模态/分屏透明度通道继续保留。
2. 按用户追加的第 4 点，应用名称与操作按钮独立判断。名称使用 Layout 实际文字边界，避免 TextView 空白宽度使能放下的文字被隐藏；完整容纳且未被省略时平滑淡入。操作按钮仍需整个操作区能完整显示。图标不受这两项条件限制。标题/操作更新不再调用带图标副作用的原厂 setTitleAlpha，避免每帧先把图标置为 INVISIBLE、再由独立图标逻辑恢复 VISIBLE，造成重复布局和绘制。
3. 在最近任务样式页选择堆叠后，在堆叠样式卡片内部、示意图下方展开缩放滑条，共享卡片底色，水平内边距与原卡片标题均为 16 dp。左侧显示“卡片缩放”，右侧显示百分比。范围为 70%–120%，每档 1%，默认 100% 等于此前的卡片大小。采用冰蓝色 4 dp 轨道与 20 dp 圆形滑块，滑条触摸高度 48 dp；覆盖原主题的轨道、滑块和着色。调整立即保存，选择标准/宫格时隐藏，重新选择堆叠或重开设置页保留数值。中文与英文标签跟随系统语言，正文颜色沿用原设置页。堆叠卡片选中后只禁用卡片点击，保留内部滑条可操作。
4. 保留桌面长按预览入口的单位父级缩放和零初始横向偏移，避免额外 1.5 倍放大。最新录屏在 112% 和 70% 应用入场中仍有大小回摆；此前仅给实时画面设缩放下限，并在末帧纠正 identity，无法保证较小目标的连续收缩，也允许中途原厂重置值改变轨迹。现在在明确提交 RECENTS 时采样松手前实时缩放，用原厂同一个动画的已缓动进度连续插值到用户目标，覆盖中途原厂缩放重置，取消二次计时或末帧补缩放。后方截图的淡入跟随相同进度。小窗、取消、快速切换等尚未提交 RECENTS 的路径继续保留原输入。实际帧率改善尚待设备验证。
5. 最新截图中虚化图标出现竖直切边，原因是截图可见范围被施加到整个 TaskView 的 clipBounds。现在将裁剪移到子视图绘制，只对截图及非图标内容应用遮挡切片，TaskViewIcon 保留完整轮廓并继续按可见空间虚化；根视图不再承载这条竖直裁剪边。手势命中另读取相同的逻辑截图边界，避免放开图标绘制后错误扩大卡片可点击/可上滑区域。删除和样式切换仍清除裁剪状态。
6. 卡片中心相对屏幕中点的偏移统一乘用户比例，卡片宽高、卡片间距和堆叠距离同比例变化。实时画面目标、截图排列与删除补位共用这一中心计算；100% 保持原布局，预加载保留范围重新验证小比例与大比例布局。
7. 用户新录屏显示拖动前方卡片时，后方小窗/菜单按钮会短暂出现。原因是截图在拖动期间放开裁剪时，也把拖动卡片从共用的遮挡边界中排除了。操作区现在使用独立遮挡边界，手指拖动和已提交删除期间均保留前方卡片的遮挡，直到卡片移除；名称仍独立判断。TaskView 绘制子按钮时还检查操作区隐藏状态，阻止原厂拖动/锁定动画重新写入 alpha 后把隐藏的小窗、分屏或菜单按钮画出来。

设置保存在桌面自身的 `ls_native_stack` SharedPreferences，键为 `card_scale_percent`，不读取模块设置。每次使用资源基准缩放乘用户百分比，不在上帧结果上重复相乘。实时应用画面终点、截图卡片、裁剪及删除补位共用现有缩放计算；原厂手势持有期间和非堆叠样式保持原处理。

缩放控件以 `LsNativeStack$ScaleControl` 挂到堆叠样式卡片的纵向容器内部。只创建一个控件，不静态持有 Activity。新增一个辅助内部类，当前允许新增类由七个精确扩展到八个；历史版本核验仍使用七个类的边界。未修改资源包，继续要求原厂资源以及相对 260005 的全部资源、assets、原生库保持一致。

## 验证与待验收

`test-launcher-stack-controls.py` 执行真实生产的控件、持久化、缩放和图标几何方法，2,530 项断言覆盖默认值、所有 51 档、重复帧不累乘、保存/重开/样式切换、控件位于卡片内部且保留内边距、越界与类型异常、实时画面与卡片比例一致、低缩放下 identity 重置、桌面预览缩放/位移及其他样式隔离、冰蓝滑条尺寸与着色、图标连续透明度/虚化/恢复/缓存/密度变化、名称和操作按钮互不绑定、实际文字宽度与连续淡入、横竖主轴及分组任务的独立图标。另检查原设置页和桌面预览接入点、标题更新不再写图标透明度，以及退出堆叠时清除虚化。

新增 `test-launcher-stack-visual-continuity.py` 执行生产入场/间距计算，637,859 项断言覆盖所有 51 档、不同松手大小、整段连续进度、中途原厂重置、大小单调变化和最终交接；另逐条解释实际 Smali drawChild 的 78 条绘制路径，确认隐藏按钮不可绘制、完整操作区允许淡入、名称与图标不受按钮隐藏影响、截图仍裁、Canvas 恢复成对且手势使用逻辑边界。该脚本已加入统一构建。

截图保留回归为 39,367 项断言，覆盖 70%/100%/120% 下尺寸与间距同步缩放的可见范围。删除补位扩大到 70%/84%/100%/120%，978,328 项检查通过；另有 53 项命中、624 项旋转和实时画面、723 项手势生命周期检查。后者增加拖动未提交/已提交删除时前方截图保持完整、后方操作区继续受遮挡，以及原厂每帧恢复按钮 alpha 后仍被隐藏的场景。它们验证代码路径与几何连续性，不代表真实 GPU 帧率。

测试使用主机 JVM 和有状态 Android 替身，不等于真实系统绘制。尚未安装、回读手机版本或完成本次实机操作验收。待复测：卡片内冰蓝拖动条实际绘制和拖动、左右滑动时图标清晰/虚化/隐藏及名称与操作区独立显示、70%/100%/120% 的桌面预览与应用入场交接、取消进入最近任务、删除补位、设置页展开/收起及重开保存、横屏和小窗取消。
