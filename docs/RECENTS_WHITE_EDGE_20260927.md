# 260019：卡片消散与横滑竖向亮边

显示版本保持 `26.9.260.908.2609081608`，本轮功能修正使用内部版本 `260019`。保留 `260018` 的两种入口退出一致性。

## 实测反馈后的追加修正

用户测试初版 `260019` 后确认卡片左侧仍有细白线。初版对 3dp 交叠和整数裁剪的处理不能覆盖全部边缘问题。

另一条可达路径位于 `TaskThumbnailViewDeprecated.drawOnCanvas`：浅色圆角底图和截图使用相同左右边界，均带抗锯齿；底图只在上下内缩 1px。原守卫仅在 `Bitmap.hasAlpha()==false` 时省略底图。硬件 RGBA 截图可以带透明通道，但任务本身完全不透明，因此旧守卫仍会重复绘制同一条抗锯齿边缘。

本次只在真实不透明截图完整覆盖绘制区域时省略重复底图。兼容原无透明通道位图，同时利用 `isRealSnapshot` 与 `isTranslucent()` 识别系统提供的不透明硬件截图。核对实际画笔的 Shader 和透明度，再读取 Shader 当前矩阵检查整张位图是否覆盖实际绘制范围；私密占位、锁定、启动占位、真实透明、缺图、矩阵留边及非堆叠样式保留背景。高通路径使用 DECAL，不能仅凭不透明任务标记无条件删除所有底图。

覆盖检查使用截图实际绘制范围，要求画笔本身 Alpha 为 255、Shader 相同、矩阵保持矩形且结果有限非空；缓存 Matrix 每次先重置，防止单位矩阵继承前一次变换。仅比较范围允许 `1/1024px` 的浮点计算容差，实际绘制和裁剪不扩张。例：float32 的 `205 / 720` 再乘 720 得到约 `204.9999847`，不能因此重新绘制一整层底色；可见留边仍走原背景路径。

`TaskView.hasOverlappingRendering()` 返回 false，淡出可能按单次绘制应用透明度。因此像素回归同时覆盖整组透明度和逐次绘制透明度两种合成：单独绘截图时都没有第二层底图带来的加亮项。DECAL 在位图外的透明采样和单次截图的抗锯齿仍由原厂 Shader 处理，主机检查不能证明 GPU 上所有细线已经消失。

构造来源核对：`ThumbnailData` 的默认 `isRealSnapshot` 实际为 true，不能单独视为来源证明；当前源码外部非空截图通过 `Companion.fromSnapshot` 从系统 `TaskSnapshot` 明确读取实际透明性，其他无参构造的 final bitmap 为 null，被缺图分支保留底色。未来新增合成截图构造来源时需重审该条件。

这是同一白线问题的追加修正，仍使用 `260019`，不新起功能版本。

追加回归通过 32,768 条实际 Smali 分支、120 项几何及特殊值用例、7,806 个 float32 缩放（含 321 个严格比较会误回退的舍入样本）和 1,728 项边缘透明度合成。检查包含真实绘制参数接线、矩阵缓存从非单位变回单位、非零绘制原点、90°/180°与镜像、斜切/留边/无效尺寸回退，以及两种 Alpha 合成模型。

旧守卫在“不透明 RGBA 应省底色”的首条行为断言失败；三个内存变体分别撤销元数据修正、移除覆盖判断、漏掉缓存矩阵重置，均按预期失败。没有改回工作区业务源码。追加修正版完整构建完成 33 步、0 失败，结果为 `signed_verified`。强制回编译、辅助 Java/Smali 同步、构建期间业务源码未变、实际版本、原升级签名、资源/代码范围及 16 KB ZIP 对齐核验通过；实际版本仍为 `260019` / `26.9.260.908.2609081608`。

### 已确认但尚未修正的圆角遮挡

用户截图还确认了独立的圆角交接缺口：当前 `TaskView.drawChild` 仍使用贯穿全高的矩形裁剪，使前卡左上、左下圆角外本应可见的后卡被提前删除。去掉 3dp 后该缺口更明显；小数精度不会改变裁剪形状。

正确方向是按前层截图的真实圆角形状进行二维遮挡，并处理路径缓存失效、退出冻结、长按及远端应用窗口的首帧交接。现有远端启动仅有矩形 crop，不能认为更换一个 `clipOutPath` 就覆盖全部交接。本次底图修正不等于圆角缺口已修复，原几何回归也没有验证二维圆角交界的像素输出。

## 录屏与原因

用户提供 `Screenrecorder-20260927-105133.mp4`（约 5.75 秒）和 `Video_1790477466209_241.mp4`（约 21.51 秒）。第一段在卡堆消散时，相邻卡片交界处出现窄竖向亮带；第二段反映左右移动时的同类问题。原始录屏及截图仅作本地证据，不随公开源码保存其中的应用画面。

`LsNativeStack.update` 原先将后卡截图裁到前卡左边缘再向内延长 `3dp`。名为 `shadowAllowance` 的余量实际作用于整张截图，并非独立阴影。在卡片透明度变化时，这一窄区同时叠加两张卡片；与录屏中约 9 像素的亮带位置和宽度相符。原裁剪还经整数取整，直接删余量仍可能产生不足 1 像素的交叠或间隙。

上述为逐帧观察与代码、主机几何验证一致的原因判断；未用修改后的真机录屏验证 GPU 输出。

## 修正范围

1. 普通滑动与长按收回时删除 3dp 重叠，后卡截图在前卡边界处结束。
2. 几何计算、长按插值及 `TaskView.drawChild` 保留浮点裁剪。旧整数设置接口委托浮点实现，触控 Rect 独立向外取整。
3. 同一整数触控范围内，小数边界变化仍会触发重绘；不到 1 像素的有效裁剪保持有效。全宽、负值及非法尺寸会清除裁剪；旧原厂根裁剪仍由现有路径清理。
4. 退出帧捕获、恢复和打开应用的可见比例使用同一个浮点边界。最终远程缓冲区裁剪继续遵守原厂整像素接口。

图标、侧边按钮的裁剪豁免保持；动画时长、透明度曲线、原厂缩略图背景与阴影绘制没有改动。本轮不扩展非中心 pivot 的既有布局假设。
