# 260017 实测反馈：删除前卡后的历史布局与横屏尺寸

本次属于 `260017` 的实测修正，内部版本不重复增加，显示版本保持 `26.9.260.908.2609081608`。用户已验收基线仍为 `260005`。

## 问题与修正

从应用进入最近任务时，第二张卡片为选中历史卡，最新应用卡位于右侧。删除右侧最新卡后，历史卡的任务序号和原厂页码同时减一。此前代码因此把历史布局切换成桌面首屏布局，造成仍在屏幕上的后卡左移、轻微缩小，以及更后方卡片间距收紧。清除原厂残留滚动差值只能避免额外跳动，不能阻止这次布局规则变化。

现在删除比选中卡更新的任务、且选中任务变为第零张时，保留当前最近任务会话的历史布局原点。删除动画终点和删除完成后的稳定布局使用同一投影。位置与缩放保持不变；继续滑动、重复删除和取消删除不会突然恢复桌面首屏间距。真正退出最近任务、重新进入或开始新的应用手势时清除该状态。重复的最近任务状态通知不清除状态。原厂任务序号、页码、任务数量和选中任务身份不增加虚拟任务。

横屏卡片宽、高改为上次尺寸的 110%，即此前未缩小基准的 `0.70 × 1.10 = 0.77`。竖屏比例、自定义缩放设置及保存值保持不变，横屏实时画面与截图目标共用尺寸读取。

实现位于 `helper-src/main/com/android/quickstep/views/LsNativeStack.java`，生成的辅助 Smali 同步至 `src/smali_classes2/com/android/quickstep/views/`。

## 验证

- 删除几何回归执行真实生产方法，覆盖不同任务数、首尾/中间/分数页、正反分页方向、非任务子视图、自定义缩放、取消与重复回调，共 980,012 项通过。
- 新增“删除更新卡后所有幸存卡位移为零、缩放倍率为一”的行为约束，并核对完成回调后的实际布局；同一测试运行修改前源码有 17,348 项失败，修改后为零。
- 手势与入场回归增加保留状态的生命周期检查；新会话重置、重复状态通知保留、退出及新应用手势重置。
- 缩放回归 8,538 项覆盖横竖屏、四种旋转值、用户缩放、连续计算、实时动画终点和恢复竖屏。

这些是主机端计算和接入检查，不能替代设备上的绘制、帧时间和触摸验收。最终构建信息见 `DEVELOPMENT_STATUS.md`。

## 录屏分析边界

本轮逐帧解码并比较了完整录屏，确认删除前卡时后卡内容约向左移动 39 个原始画幅像素。原始帧、时间戳、差分、局部跟踪结果和详细分析保存在本机被忽略的审查目录，不将用户应用画面或设备数据写入公开源码。

另外记录了长按展开/收回时背景卡片大范围移动、应用打开过程中短暂黑帧的观察。它们的视觉现象与本次删除布局修正分开记录，未声称已修复。横屏录制画幅切换不能单独作为桌面强制转竖屏的证据。
