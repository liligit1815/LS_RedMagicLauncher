# 260017 横屏入场交接与堆叠尺寸实测修正

本次为 260017 的继续实测修正，不重复增加内部版本；显示版本保留 `26.9.260.908.2609081608`。

## 前卡偏上后恢复

录屏中实时应用前卡在入场末段仍位于屏幕副轴中心，切换为任务截图时才向下回位约 60 个原始画幅像素。偏移发生在录屏画幅转向之前，不能解释为录像旋转。

原厂 `TaskView.setPivot()` 的 X 轴缩放中心取整个 TaskView 宽度的一半；两个横屏方向的 `setTaskThumbnailOrientationState()` 分别给截图增加右侧或左侧标题边距。整个任务视图中心与截图实际中心因而不重合。原来的实时画面目标只对齐任务视图中心，忽略了截图相对该中心的偏移。

现在按实际截图位置、尺寸和 TaskView pivot，计算缩放后的截图中心偏移，再通过同一窗口旋转矩阵映射。已采样的手势动画路径与未取得首帧采样的备用路径都使用该目标。在截图接管前完成对齐，避免先在偏上位置停稳、接管时再回位。该修正仅作用于视觉横屏；竖屏投影保持原逻辑。未确认进入最近任务时仍由原厂小窗、快速切换和取消手势拥有实时画面。

实现：`helper-src/main/com/android/quickstep/views/LsNativeStack.java` 中 `offsetLiveSnapshotCenter()`、`applyLiveGestureBounds()` 与 `normalizeLiveEntryMatrix()`。

## 尺寸与间距

- 横屏卡片宽、高在上次 0.77 的基础上各乘 1.05，新比例为 `0.8085`，即原始未缩小基准的 80.85%。
- 横屏中心间距系数为 0.90，围绕视口中心收紧。历史页、桌面首屏后卡特殊位置、两者之间的滑动过渡均采用相同系数。
- 尺寸与间距每次从用户原始设置重新计算，不逐帧累乘；返回竖屏时方向间距系数恢复 1。用户保存的 70%–120% 自定义缩放值不改写。
- 实时画面目标、截图最终布局和删除动画共用对应尺寸、位置规则。保留上一轮删除前卡后历史卡不左移的修正。

## 验证与边界

- 实时画面投影回归 15,275 项通过，覆盖两种横屏方向的左右标题边距、不同缩放、连续入场帧、备用路径、窗口旋转与位移、小窗/取消隔离。相同新增检查在修改前源码上失败。
- 尺寸、方向、间距系数与设置持久化回归 10,939 项通过。
- 删除几何检查在间距系数 1 与 0.90 下合计 1,960,024 项通过，包含之前前卡删除后的零位移、零缩放变化约束。
- 桌面首屏与历史页新增统一间距收缩检查，避免只改变历史页而在回到第一页时跳变。

最终 APK 的版本、签名与构建信息以 `DEVELOPMENT_STATUS.md` 当前小节为准。该历史修正的记录限于主机回归与包内核验，不包含设备帧率或画面采样。原始视频、逐帧图像和局部测量仅保存在本机被忽略的审查目录，不随公开源码保存。
