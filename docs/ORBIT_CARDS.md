# 环绕卡片（260023）

最近任务样式新增第四项“环绕卡片”，参考用户提供的 `环绕卡片.gif`。内部版本为 `260023`，显示版本保留 `26.9.260.908.2609081608`。

## 使用与行为

在桌面设置的最近任务样式中选择“环绕卡片”。选项包含独立预览，关闭设置后保留选择，设置摘要同步显示名称。

- 卡片保持竖立，沿竖向椭圆轨道移动：下方前景卡较大，上方远景卡较小，左右卡片部分露出。按实机反馈将横纵轨道半径同步收紧 15%，保持圆心和卡片大小，让各卡片更靠近圆心。
- 横向滑动使用独立的连续环绕位置，支持拖动、松手惯性和卡片吸附；朝同一方向可持续滑动，双向越过首尾。位置、大小和遮挡层次随环绕进度变化，不复制任务或创建重复的 TaskView。
- 六张以内的任务均匀分布在环上；更长的历史只显示当前环形窗口内最多六张卡片，跨首尾预载邻近任务截图。后方卡片在距离焦点两至三个位置之间渐隐，最远位置的换向发生在完全透明时，避免多圈卡片重叠。单任务保留下方前景位置。
- 点击、上滑删除和长按操作按实际可见区域与前后层次命中，远景卡也可操作。循环拖动保留原点击与长按观察，竖向删除仍走原厂动作；长按复用现有侧边操作。
- 删除或打开应用时冻结当前环绕位置，由对应动画接管；正常点击、长按及竖向删除不会把位置拉回原厂分页边界。新一次最近任务入口或样式复位会清理旧位置，删除成功后将环绕位置与原厂选中任务同步提交。
- 删除任务时，其余卡片在原厂删除动画的同一进度内补位，同时改变横纵位置、大小和层次；删除末尾焦点任务后接回首张任务。取消、下拉锁定和过期回调不提交补位。
- 桌面入口、应用入口和退出复用现有交接流程，实时应用画面的终点使用环绕布局。点卡打开时，截图与实时应用窗口使用同步的变换矩阵，取消或结束后清理截图的临时变换。方向转换使用最近任务的视觉方向。
- 环绕卡片单独适配视口尺寸，100% 比例下前景卡宽不超过视口的 48%，高不超过视口的 42%；轨道圆心位于视口横向 50%、视觉纵向 42%，横纵半径分别为对应视口尺寸的 49.3% 和 18.7%。前景中心位于视觉纵向的 60.7%，卡片底部不超过 81.7%，为原厂底部操作留出空间。从 260025 起环绕有独立的 70%–120% 比例滑条，默认 100%；上述尺寸为 100% 基准。比例保留轨道形状与间距；视觉横屏大于 100% 时，若前景卡底部超过原 100% 的安全边，整组沿视觉纵向上移相应距离，为清理按钮留白。实际卡片比例不被钳小，布局、实时窗口与删除补位使用同一位移。堆叠与扇形比例不影响环绕。

普通、网格、堆叠、环绕分别保存为 `1/2/3/4`。环绕与堆叠共用手势生命周期，几何和裁剪分开；环绕不使用堆叠的单向截断。

## 实现位置

- `TaskView.smali` 与 `LsNativeStack.shouldDispatchOrbitCardTouch()`：从 `260026` 起，在环绕子视图接收 `ACTION_DOWN` 前使用与长按一致的可见卡面命中，拒绝透明空白和被上层卡覆盖的容器。同 Z 按较后子视图优先，与 Android 绘制顺序一致。后续原厂点击与取消流保持原有目标；本轮不更改删除手势命中。
- `LsOrbitGeometry.java`：不依赖 Android 的循环轨道几何；`normalizePage()` 规范化任意圈数的位置，`distance()` 计算最近有符号环距，统一驱动坐标、缩放、透明度和前后层次。
- `LsOrbitPager.java`：独立水平拖动、惯性及吸附，保存连续环绕位置；只在确认横向拖动后接管触摸，负责停止、提交及清理位置状态。
- `LsOrbitReflow.java`：绑定任务身份的二维删除补位，接入原厂 PendingAnimation；删除焦点后按循环顺序选择任务，并预载补位前后需要的截图。
- `LsOrbitStyleSettings.java`：设置项、名称和程序绘制预览，复用现有主题及资源。
- `LsNativeStack.java`：将环绕位置接入实际布局、截图驻留与删除采样；管理实时画面目标、标题图标、可见区域和生命周期分支。
- `LsStackTransition.java`：点卡打开时同步截图与实时窗口矩阵，保存并恢复截图原有动画矩阵，沿用原厂动画进度。
- `RecentsView.smali`：样式识别、环绕可见卡判断、长按观察之后及原厂分页之前的循环手势路由，以及删除动画回调。

辅助 Java 必须经 `tools/build-launcher-helper.py` 同步到打包 Smali。发布通过 `tools/build-launcher.py`，仍对照固定 `260005` 基线；没有修改原厂资源、原生库、assets、签名身份或父模块。
