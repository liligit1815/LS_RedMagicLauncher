# 260009：取消小窗与手势条切换期间保留原厂截图动画

显示版本保持 `26.9.260.908.2609081608`，内部版本 `260009`。固定验收基线仍为 `260005`，保留 260006–260008 的修正。

## 问题和范围

用户确认上一版小窗动画已经恢复，进一步说明半截画面发生在“拖动 app 去小窗的过程中，放弃去小窗的操作”，并反馈滑动手势条切换后台没有动画。本轮提供的两段录屏包含连续应用切换及局部截图暴露；取消小窗的具体触发条件以用户文字澄清为准，不能将录像中的每个局部画面都认定为同一种缺陷。

260008 仅限制了 TaskViewSimulator 实时应用画面的矩阵、缩放和滚动修正。最近任务的截图 TaskView 仍由 `LsNativeStack.update()` 在每帧重新合成，即使原厂正借用最近任务视图执行快速切换或取消小窗。它会裁剪后层卡片、修改缩放和位移，待入场回调还会将原厂分页重新定位。这是可由源码和回归重现的干扰；是否完全解释设备上的全部动画异常仍需安装复测。

## 修正

- 在 `RecentsView.onGestureAnimationStart()` 的原厂初始化之前调用辅助层，解除缓存任务的堆叠裁剪、变换和标题透明度，并取消旧入场状态。保留 TaskView 自身的原厂动画字段。
- 使用关联当前 RecentsView 的弱引用记录原厂手势所有权。在这段期间，截图合成、待入场提交、状态预备、触摸接管及动画结束回调均不能重新定位或裁剪卡片。加载回调直接执行原厂要求的 `setCurrentPage()`，包括同页重新对齐。
- 不在通用“手势结束”回调里立即恢复堆叠，防止取消返回应用或切换应用之后的延迟回调再次截断画面。
- 原厂明确决定结束目标为 `RECENTS` 时恢复堆叠及应用进入时的第二张卡片聚焦。从桌面再次进入最近任务时也解除原厂手势所有权。
- 不修改原厂小窗判断、快速切换动画器及阈值，不添加延迟补动画。

## 回归与待验收

`tools/test-launcher-native-gesture.py` 提取生产 Java 的完整 `update()`、重置、生命周期、分页及入场队列方法，通过模拟视图记录真实写入；几何曲线由既有独立测试覆盖。149 项断言包括冷启动/缓存卡片、取消及快速切换的共用非 RECENTS 路径、完成回调先后顺序、同页对齐、旧队列、明确进入最近任务、桌面重新进入和原厂样式隔离。260008 源码在“拖动时重新合成截图”检查失败，修改后通过。另检查 Smali 接入先于原厂手势状态初始化。

这些是主机回归，不能代替 Android 设备渲染。当前没有连接 ADB 手机，未安装、未回读手机版本。待复测：拖向小窗再放弃返回应用，反复拖入/移出触发区，松手成功进入小窗，左右滑动手势条连续切换应用，正常进入最近任务、返回桌面后再次进入，以及横屏对应路径。录屏和抽帧仅保存于本地忽略目录。
