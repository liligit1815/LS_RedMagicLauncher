## 行为与实现

### 实时应用画面接续到截图卡片

应用进入最近任务时，仅衔接缩放值仍不足以保证连续：原厂还会改变矩阵、裁剪和任务尺寸；相邻卡片若在交接时被设为透明，也会出现消失后重新淡入。

`LsNativeStack` 按实时画面的矩阵实例保存原厂最后可见矩形。只有结束目标明确为最近任务时，才沿原厂动画进度接续到实际截图尺寸，并把同一坐标映射应用于旋转后的窗口。相邻卡片记录各自实际位置与显示状态，跟随同一进度接续；已显示的截图不先隐藏。小窗拖动、取消和快速切换继续保留原厂变换。

入口终点规则保持：桌面进入时顶层卡居中，后卡从下方向左展开；App 进入时前卡在右、第二卡居中，后卡向左展开；单任务居中。用户的 70%–120% 缩放继续生效。

### 首屏后卡间距

11:24 录屏中入场 reveal 已结束，首屏后方卡片仍露出过密窄条。代码对应原因是原堆叠中心按指数收敛，更多后卡挤在相近位置；本次修正针对稳态几何分布，录屏本身不能证明动画帧率异常。

`getMiuiStackCenter` 将前卡左边距到 2.5% 安全边之间的可用空间均分给前两张后卡，使用固定两个位置，不因任务数量从三张变为两张而重新分配。修正量在第 0 页到第 1 页之间以 smoothstep 平滑衰减，继续翻页时回到原排列；普通 `update`、实时入场 `live` 和删除补位 `dismiss` 共用同一目标，避免各阶段目标不一致。

### 长按展开完整侧边操作

参考录屏显示独立白色圆形按钮沿弧线排列，按钮、所选卡片与其他卡片同步运动。本轮用 `LsStackActions` 替代所选卡片原右上角的小窗/更多按钮。新的逐帧对照显示：同一 QQ 卡片居中时按钮在右，移到屏幕右侧后按钮在左，期间仍遮挡白色卡片。因此侧别与展开前的位置有关，不能只按任务顺序或可见层级确定；录屏尚不能给出原厂精确的数值阈值。

本工程明确采用以下规则：在长按成立时，将所选任务每个容器的完整截图框通过实际矩阵映射到屏幕坐标，多容器取这些完整框的并集。其水平中心小于或等于根视图（root）对应物理屏幕中线时，操作显示在物理右侧；大于中线时显示在物理左侧。判定使用完整截图框，不取被其他卡片遮挡或裁剪后露出的片段，也不由列表序号或 Z 层级决定。这里的中线是本工程采用的明确规则，并非声称从视频测得原厂阈值；横竖屏和 RTL 均按物理左右解释。

位置采样发生在清理旧菜单和结束入场之前，保留长按成立瞬间的画面位置。对同一任务、同一次仍在进行的菜单，展开、反向收回和中途重开均锁定首次选择的侧别，避免卡片让位或其他卡片淡出后翻侧；该次菜单完全结束后，下次长按才重新采样。

侧栏从原厂 `TaskOverlayFactory.getEnabledShortcuts(TaskView, TaskContainer)` 取得可用动作，复用名称、资格与执行器，包含锁定/解锁、分屏和应用信息等符合条件的操作。锁定动作按原厂要求先初始化图标与标题容器，保证状态显示与点击行为一致。已知操作采用下面说明的统一线形图标，未知动作保留原图标；参考录屏中功能未确认的彩点图标不被臆造为新功能。

小窗原有两条入口：菜单工厂的分支要求 `X3.b()` 为 true 且 `N5.F()` 为 false；卡片独立按钮则在 `N5.F()` 为 true 或 `X3.b()` 为 false 时继续检查任务资格。侧栏替代独立按钮后，仅依赖菜单工厂会漏掉后一条入口。现仅在单任务容器、菜单缺少小窗且独立入口仍可用时补入原 `MiniWindowSystemShortcut`，不重复添加，也不向分屏组合任务扩展。

新增能力桥接调用原 `TaskView.updateMiniWindowButtonState()`，保留系统开关、任务 `supportResize`、外屏和设备按钮启用条件，再恢复原按钮 visibility，避免读取资格时改变隐藏状态。标题是否隐藏不再误充当能力判断。文字 `mini_window_label` 和 `startMiniWindowMode()` 执行链保持，侧栏图标随本次统一为线形，原资源 `small_window` 不修改。点击与收回完成后的延迟执行只对这个新增入口重验资格，原厂菜单已有小窗保留自己的资格路径。任务身份和最近任务存活条件仍必须满足。

展开时间为 300 ms：所选卡片移向预留按钮空间的另一侧，并按可用宽度限制尺寸；其他卡片向外移动并淡出，标题与图标按同一进度隐藏。按钮以短错峰从卡片方向滑入、放大和淡入，弧线及间距根据可用屏幕尺寸计算，并避开系统栏和刘海区域。

非选中卡片此前沿用静止堆叠时的固定截图片段，离开原遮挡位置后仍半截淡出。该片段由 `TaskView.drawChild` 的独立 Canvas 裁剪控制，仅清理 `View.clipBounds` 不会解除。现在从原片段按 `smoothstep(p / 0.55)` 连续补到全宽，在展开进度 p 达到 55% 时解除额外逻辑裁剪。前 15% 保留原透明度，随后使用 `1 - smoothstep((p - 0.15) / 0.85)` 淡出，各输入均限制在 0–1；恢复全宽时仍保留约 54.4% 的原透明度，终点为透明。

卡片原有 Z 顺序继续提供自然遮挡，截图沿用原厂圆角，不改为矩形图片；移出屏幕的部分仍由屏幕边缘裁切。邻卡标题、图标跟随父卡片淡出，保留独立的空间遮挡规则。关闭沿相同进度恢复静止片段，中途收回、重开和取消不切换到另一条裁剪路径。

11:24 实测中，1216 px 宽屏的白圆约 143 px，原四边 28% padding 又压缩了图标可用区域。该屏白圆目标现保持约 175 px，padding 为 23%；图标 ImageView 以 MATCH_PARENT 填满实际按钮容器，圆形背景与触摸区域一致。

参考高清帧测得圆径约 172 px、端部与中央按钮的横向中心差约 98–110 px、相邻纵向中心差约 205–212 px。弧线最大横偏保持 0.60D；本次外观修正将相邻中心间距从 1.20D 略收紧为 1.16D：上下端部贴近卡片，中间向屏幕外侧鼓，左右镜像。端部距完整截图外侧 8 dp，整列在系统安全边内另留 12 dp；卡片预留宽度仍为屏宽 32% 与 112 dp 中的较小值。参考测量是视觉近似，本工程的数值是实现选择。

本次截图对照确认主要差异在图标的粗重程度：现有白圆约 174 px，参考约 170 px，但截图屏宽不同，不能直接视为同一比例。本次保留本机约 175 px 白圆和点击区域，将信息、分屏、锁定/解锁、固定、小窗统一为深灰圆角细线。`ActionIcon` 在 24 单位视口使用 1.3 单位笔宽，配合 23% padding 后约为实际圆径的 2.9%，图形长边约为圆径的 39%；信息图标的圆点以实心圆帽短线绘制。未知动作不替换图形，也不增加参考图片中含义未确认的功能。

先调用原 `setIconAndContentDescriptionFor` 保留名称、无障碍描述和启用状态，再替换已知动作的图形。锁定/解锁图标读取原 `isAppLocked(task, x1.O.Q0())`；禁用状态使图形和白圆一起降到 0.38 透明度。每个按钮有独立 Drawable，按实际 bounds 等比居中，支持 alpha、ColorFilter 和空边界，不改白圆触摸区域。唯一新增生产内部类是 `LsStackActions$ActionIcon`，本轮 helper 精确白名单合计 17 类，原厂资源不修改。

侧栏仅按 `CloseSystemShortcut` 类型移除关闭叉号，再按实际剩余按钮数计算弧线、错峰和整列高度；不按位置删某一项，不改原厂菜单列表和底部清理按钮。其他动作仍在侧栏收回后执行原厂处理。

同时修复了尺寸计算问题：转屏重测量时，旧实现会取旧布局尺寸与新测量尺寸的较大值，随后布局又按新尺寸计算间距，导致容器过大并互相重叠。现在仅从新 MeasureSpec 计算一次整数圆径，测量、布局及 padding 共同使用它；可用高度不足时按按钮数量和整列间距一起缩小，保持安全边界及与放大卡片的距离。

侧栏作为 `BaseDragLayer` 下的完整浮层参与原厂返回键和浮层关闭生命周期，覆盖区域消费触摸，避免点按钮或空白时穿透到卡片。初始长按松手保留侧栏。点击外部、返回或选择动作后，用 220 ms 从当前进度反向收回；收回完成后才调用原厂动作。旧动画回调、任务复用、离开最近任务和取消不能执行过期动作。

### 退出最近任务与点击打开应用

`LsStackTransition` 在退出清理之前捕获每张卡片实际平移、缩放、层级、裁剪和任务身份。退出中的更新复用该画面，并补偿原厂分页滚动引起的位置变化；透明度继续由原厂内容淡出驱动。退出完成后的隐藏阶段不接受晚到的重置覆盖，下一次入场或原厂手势重新接管时清理事务。

点击单任务时，从 `TaskView.launchWithAnimation` 捕获当前截图相对于根视图的矩形，`TaskViewUtils` 将它绑定到原厂实际 `TaskViewSimulator`。真实应用远程动画以该矩形接续，几何偏差随原厂 `fullScreenProgress` 衰减到零，裁剪逐步放开。原厂 ActivityManager、远程目标、SurfaceTransaction 以及完成流程保留。分屏组继续使用原厂路径。

取消、启动失败、重进、任务身份改变或旧监听器回调会清理对应事务，防止冻结状态影响后续分页或将旧任务的矩形用于新任务。

### 长按偶发无法触发

原长按只在 `TaskView.dispatchTouchEvent` 收到 DOWN 后启动 250 ms 定时器。原厂分页器在停止未结束的惯性滚动时可以直接拦截 DOWN，子卡片因此收不到事件，按住不动也不会启动计时。这是本轮已在主机回放中复现的失效路径。

新增 `LsNativeStack.dispatchCardLongPressTouch(RecentsView, MotionEvent)`，在侧栏触摸处理之后、原厂父分页器分发之前观察原始事件。按逆矩阵、截图裁剪和实际层级选择触点处的可见卡片，只接受截图或可见标题、图标；清理按钮、屏幕空白与卡片内部留白不计为卡片。子卡片直接派发的 fallback 也使用相同内容边界。

同一指针与 downTime 的重复 DOWN 保留第一次计时；小幅抖动按每个坐标轴的系统 touchSlop 判断。超过阈值的横滑/上滑、多指、原始 CANCEL、UP、任务解绑或身份改变都会终止计时。父分页器为内部拦截而发给子卡片的 CANCEL 不覆盖父层观察到的真实按住状态。阈值继续取 250 ms 与系统长按时间的较小值，不修改系统全局配置。

触发后，`RecentsView.cancelNativeStackTouch(MotionEvent)` 先重置原厂拖动状态，再直接将 CANCEL 交给原厂分发，取消任务点击与分页手势，避免长按松手启动应用或分页器继续吸附。原始长按释放由侧栏消费并保留展开状态。`canLaunchFullscreenTask()` 为 false 的分屏选择状态使这次按压失效，不通过固定延时重试进入后来的其他状态。非堆叠样式继续使用原厂交互。

### 普通短点击保留原厂状态

11:24 的短点击失效发生在普通 UP 清理阶段：自定义长按尚未触发，却调用了原厂 `cancelLongPress()`，使原厂用于完成点击的 `PREPRESSED` 标志提前清空。普通 UP 现在只移除自定义长按计时器，随后保留原厂 UP 与点击处理。真正长按成立、滑动、多指及取消继续按各自边界结束触摸，不把普通点击清理扩大为取消原厂点击。

## 真机复测重点

1. 从桌面、应用和单任务进入，观察松手交接处的尺寸、中心与相邻卡片是否连续；首屏前两张后卡应清晰分开，三张减为两张时保留卡片不跳位，翻到下一页时平滑过渡。覆盖横竖屏及 70%、100%、120% 缩放。
2. 将同一任务移到屏幕中线两侧分别长按，确认完整截图中心在线上或左侧时按钮在右、右侧时按钮在左；覆盖部分屏外、被遮挡和多容器卡片，确认使用完整框并集。按钮不越过安全区域，初次松手不打开应用。
3. 先反复短点卡片，确认普通松手可以打开应用；再快速左右滑动后按住，确认惯性停止时长按仍能触发。对照轻微抖动、明显横滑、上滑、多指和按住清理/空白区域均不误触，长按松手不误启动应用。
4. 在展开、关闭和中途反向操作时观察卡片、标题、按钮是否同时连续变化：非选中卡片应在仍清晰可见时补全截图后继续淡出，回收恢复原堆叠片段，圆角和层级保持。同一任务中途重开保持侧别，菜单完全结束后重新长按按新位置选择侧别。
5. 检查白圆尺寸、细线图标、略收紧的间距、弧形、贴边距离和实际点击区域；核对锁定/解锁图形、禁用状态与未知动作图标。确认仅侧栏关闭叉号消失，底部清理仍存在且可用。覆盖横屏窄高、展开时转屏与不同操作数量，确认无相邻按钮或卡片重叠；验证小窗、外部点击、返回、锁定、分屏和应用信息操作。
6. 退出到桌面与点击各层单任务打开应用，检查是否先跳回默认排列；快速取消、失败、重复进入和任务变更后确认没有冻结、错位或过期操作。
