## 08:33 录屏与最终明确的规则

用户通过 `Screenrecorder-20260926-083339.mp4` 明确：问题是桌面上滑后卡片堆叠拥挤、缺少预期展开。最终要求为：桌面入口顶层卡居中、后卡向左展开；App 入口前卡在右、第二卡居中、后卡向左展开。操作按钮改为所有卡片默认隐藏，仅长按所选卡片显示其原厂按钮。此按钮规则替代“默认第一张显示”。

录屏顺序解码共 870 帧，1216×2688，末帧时间戳 8.154644 秒。连续帧 369–408（3.623–3.949 秒）、约 532 帧起（5.031 秒起）及 685–717（6.356–6.625 秒）均有整组上移/缩放，但后卡直接采用终点堆叠间距，缺少从顶层卡下向左分开的过程。本次保留桌面第 0 页和 App 第 1 页各自的终点，桌面后卡中心从顶层卡中心连续插值到各自原有堆叠落点；前卡横向中心固定。每帧裁剪同步采用展开后的中心，因此后卡从顶层卡下逐步露出。只有一个任务时继续居中；结束后恢复原有稳态几何，不改任务顺序或用户缩放。没有第二个计时器或末帧补跳。

按钮透明度现在仅由长按选中任务及展开进度决定，包括第一张和单任务在内的默认按钮均为 0。操作完成/取消后全部隐藏；打开更多仍保持选中任务，实际移除菜单后才退出。Android 的透明按钮仍能接收触摸，因此隐藏按钮区域另按真实几何拦截，不依赖当前 alpha；原厂临时写回 alpha 也不能使未长按卡片的按钮命中。其他样式沿用原厂处理。

## 实现

- 桌面入场等待有效任务布局且原厂内容透明度大于 0.01，再运行 360 ms 过渡。整组任务从用户尺寸的 78% 放大到 100%，从次轴尺寸的 24% 偏移上移至终点；辅助淡入在运动进度前 18% 完成，避免与原厂淡入长时间叠加。卡片尺寸和中心间距采用同一缩放因子，桌面顶层卡保持居中，后卡从其下方逐步向左展开到原有堆叠落点；单卡保持居中。应用内进入仍使用原实时手势动画。
- 保留 250 ms 长按阈值。触发后用 300 ms 将选中卡片移至中心并展开到用户设置大小，其余卡片向两侧移动并淡出，选中卡片右上角原厂按钮淡入。包括第一张在内的全部卡片默认隐藏按钮，仅长按所选卡片的按钮随展开淡入。卡片的实际分页和滚动位置不因长按改变，截图裁剪使用同一帧的动画几何。
- “更多”打开成功后保持选中卡片及图标名称临时规则。两种原厂菜单打开分支均报告真实结果；打开失败则退出。原厂关闭开始回调继续执行原有逻辑，辅助恢复改为同步/异步两条实际移除菜单路径之后，以任务视图和任务 ID 核对归属。
- 操作结束或取消后，用 220 ms 返回原堆叠位置，再恢复默认图标、名称空间规则并隐藏全部操作按钮。外部点击用于取消时消费整个触摸流，避免同时启动应用。取消过程重按从当前进度继续；旧动画回调、任务替换、退出最近任务和样式切换不能复活临时状态。

主要代码为 `helper-src/main/com/android/quickstep/views/LsNativeStack.java`，原厂接入为 `TaskView.smali` 与 `TaskMenuView.smali`。新增 `ActionReveal` 辅助内部类，新增类边界由九个精确扩展到十个；旧版本按原有数量核验。未修改按钮布局、资源、菜单选项或其功能执行代码。
